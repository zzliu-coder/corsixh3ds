# 双屏布局（0.6.0）

0.5.0 之前，下屏是一套自制管理面板：5×7 像素的手画字体、HOME/BUILD/STAFF 之类的
标签页、一个绿色网格。它是移植早期的脚手架，看起来像测试界面，而且和游戏本体是两
套东西 —— 玩家在下屏点的按钮，要经过一层动作编码再翻译回 Lua 去调游戏的对话框。

0.6.0 换成：**两块屏幕显示的都是游戏本身。**

```
上屏 400x240   CorsixTH 帧的 1:1 居中裁切
               ┌────────────────────────────────┐
               │  医院世界，原始像素，无缩放      │
               │  取自 640x480 帧的 (120,120)    │
               └────────────────────────────────┘

下屏 320x240   同一帧的精确 2:1 缩略
               ┌────────────────────────┐
               │  完整 640x480 界面      │
               │  工具栏 + 所有对话框     │
               │  触摸坐标 ×2 = 游戏坐标  │
               └────────────────────────┘
```

## 为什么这么分

CorsixTH 的界面是按 640×480 设计的，六个全屏对话框（城镇地图、银行、研究、员工管
理、报表、病例本）都是 640×480 的位图。改内部分辨率会把它们裁掉，属于功能损失。所
以 640×480 必须保留，问题只是两块小屏怎么分这一帧。

- **上屏走裁切而不是缩放。** 640×480 缩到 400×240 要丢掉一半以上的像素，主题医院
  的精灵本来就小，病人会缩成八九个像素高。1:1 裁切让每个像素都是真像素，代价是一
  次只看到 400×240 那一块 —— 而地图本来就要滚动，这个代价很小。
- **下屏走精确 2:1。** 640×480 恰好是 320×240 的两倍，缩放没有任何取整误差，触摸
  映射就是一次乘 2。玩家手指按在哪个像素上，游戏收到的就是那个像素。整套自制面板
  的动作编码层因此可以在触摸这条路径上完全绕开。

## 实现

| 环节 | 位置 |
|---|---|
| 上屏裁切 | SDL2 N3DS 帧缓冲补丁的 crop 模式，由 `CTH3DS_SCREEN_MODE` hint 选择 |
| 游戏窗口注册 | `render_target` 构造函数调用 `cth3ds::runtime_set_game_window()`（SDL2 无法枚举窗口） |
| 下屏镜像 | CorsixTH present 之后 `cth3ds::runtime_after_frame()` → `halve_rgba()` |
| 触摸映射 | `ScreenLayout::bottom_touch_to_legacy()`，注入 `SDL_MOUSEMOTION` / `SDL_MOUSEBUTTONDOWN` / `UP` 到游戏窗口 |
| 右键 | B 和 X 直接在最后触摸点注入右键（主题医院用右键取消和旋转物件） |
| 左键 | A 同理，注入左键，不用抬手去摸触摸屏 |

两块屏幕的像素格式都是 `SDL_PIXELFORMAT_RGBA8888`，所以镜像是纯粹的像素搬运，不做
格式转换。

SDL 自带的「触摸合成鼠标事件」会和我们自己的映射打架，`initialize()` 里用
`SDL_HINT_TOUCH_MOUSE_EVENTS=0` 关掉。

长按**不**映射右键：按下时左键已经按下去了，再补一个右键会让一次触摸变成「一次点击
加一次右键」。右键放在 B 和 X 上 —— 手持触控笔时左手拇指仍然够得到。

按键与触摸共用同一个光标：面部按键直接在 C++ 里按最后触摸位置注入点击，不走 Lua
适配层里那个独立的十字键光标，避免两个光标对不上。

## 下屏还剩什么非游戏内容

只有一条 13 像素高的状态条，而且只在两种情况下出现：

- 启动后 6 秒内，显示 overlay 版本和适配层来源（`0.6.0 LUA`），用来确认跑的是哪个
  二进制 —— 见 `docs/BOOT_DIAGNOSTICS.md`；
- 有错误提示时，红底显示错误。

平时下屏是纯粹的游戏画面。

## 回退

在 SD 卡上建一个空文件：

```
sdmc:/3ds/corsixth/bottom-screen-panel.txt
```

下屏会切回 0.5.0 的自制管理面板。用于镜像路径在真机上出问题时不用重新编译就能对
比。删掉文件即可恢复。

上屏同理：`CTH3DS_SCREEN_MODE` 设成 `fit` 会回到等比缩放加黑边的旧行为，该模式的
像素级正确性同样有测试覆盖（`tests/test_letterbox_equivalence.py` 两种模式都测）。

## 成本

下屏镜像是 76,800 次像素搬运，约 3 ms，而且每帧都要做（画面一直在变，不能像旧面板
那样跳过）。上屏裁切是 96,000 次搬运，比旧的缩放路径略便宜，且 **crop 模式下整条
present 路径连一次除法都没有**（`scripts/check_arm_codegen.sh` 会断言这一点）。

净效果相对 0.5.0 大约 +3 ms/帧，换来的是两块屏幕都显示真实游戏画面，以及触摸可以
直接操作原版界面。
