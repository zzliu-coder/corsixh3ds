# R56：复用实际工作，分开测量，保留 R55 成功路径

## 起点与目标

R55 `55b0a2799e1966a940c26eeab348b1401a3779f8` 真机 GPU 五段读回通过，用户确认明显流畅。
同一自动医院副本 Normal 有效段约 10.62 次呈现/秒，模拟吞吐约原速目标的 58%。
随后一段实玩约 10.98 次/秒；逻辑平均 58.99ms/呈现，绘制 25.47ms，温度约 14.52ms/次。
这些是阶段耗时，GPU 队列耗时与 CPU 工作有重叠，不能相加当作硬件利用率。
用户仍观察到弹窗短停顿；日志出现最长约 2.82 秒的输入动作，具体弹窗身份缺失。
30FPS、原速时间推进、繁忙医院容量和完整长期稳定性继续待验。

## 已实现的最小边界

1. **观测从运行时控制中分离。** `RuntimeObservations` 只接收数值快照，保留
   10秒摘要、60秒明细和终止时未闭合区间。存读档/切场景调用显式
   `operation_boundary`；修改日志开关不再暗中重置模拟时间。
   结构提交 `f5d29b4` 与性能提交分开，便于回退比较。
2. **GPU 图片仅转换一次。** 图片创建时生成 GPU 块顺序的紧凑 CPU 副本，
   图集换页直接复制整块，边缘保留逐像素拷贝。图集预算仍为 3MiB，
   CPU 图像载荷仍为 width×height×4；没有另存原始副本或整图边缘填充。
   绘制顺序、透明/翻转/裁剪、R55 行坐标、队列同步和全线性内存刷缓存契约保持。
3. **温度结构按变更刷新。** 每次仍快照当前温度并发布原频率计算结果。
   房间/医院/通行/暖气结构复用已有缓存；固定上游的五个地图入口和五个
   Lua 写入口负责失效通知。通用算法默认完整扫描；生产快速模式有运行标记
   `thermal-reference.txt` 作完整扫描对照。没有减少温度更新次数或改经营规则。
4. **卡顿可归因。** World 的日期/动画/医院/实体/地图/界面/分派七段有独立计时。
   真实冷加载记录资源名称，输入记录动作名称，窗口变化记录类型。
   慢事件环固定32条、阈值50ms，溢出计数，随正常摘要写出；无逐像素、逐实体计时或逐事件写卡。

新增计数 `gpu_prepare` / `gpu_upload`、`thermal-cache` 与 `world_*`。
World 分段不重排原函数调用，GPU/World 子项属于包含关系，不能重复累计。
慢事件里的 owner 是观察到的当前窗口；构造新窗口期间仍可能显示前一个窗口，
应结合资源名与下一条窗口切换记录判断，不能把相关性直接当作原因。

## 验证与设备放行

主机逐像素用独立原公式、tex3ds oracle 与实际渲染实现对照，包含多片大图、
延迟执行、图集驱逐、四种翻转、透明和初始化失败。
温度比较固定上游真实函数、泛化边界、真实 Lua 写入口及未变化期间缓存复用；
World 比较完整实际方法的调用顺序、日期和速度；C/Lua 跟踪保留 nil/多返回值/异常。
完整验证回执、最终 commit/tree、ELF/3dsx 摘要在本轮现场记录。
本文件描述施工；主机通过、交叉构建、上传读回、真机运行分别判定。

R56真机使用与 R55 相同的 `Benchmark/input.sav`（SHA256
`9e7e77fc5f05e7545b9941518726ae614d5069c4bfc16f5571ecd437622518de`）：
两档各30秒预热和60秒采样，自动恢复 Normal，约4分钟后可以人工游玩。
人工只需打开员工/建造等常用窗口、放入及移除暖气、存档/重开恢复。
用户存档与自动测量副本隔离，安装只传变化的程序/Lua/身份清单。

判据：GPU 五段正确；相同 Normal 样本呈现率与模拟吞吐均比较 R55，不能仅看动画体感；
结构扫描少于更新次数且施工后刷新；图像 CPU 载荷没有多一份；无输入失灵、
存档失败或持续内存损失。30FPS目标需要真机证据，当前不预先宣布达成。
