# 已知限制

1. 已在本机用 devkitARM、libctru、SDL2 N3DS 和固定静态依赖完成 `.3dsx` 最终链接；
   **当前没有 Old 3DS 真机证据**。0.5.0 的所有性能改动都基于 ARM 目标编译产物的
   静态分析（见 `docs/PERFORMANCE.md`），尚未在真机上测量过。
2. 模拟器验证移植层 UI 和输入，不运行完整 CorsixTH 医院画面。
3. 主画面使用 SDL2 N3DS 软件帧缓冲。0.5.0 把 present 的每像素成本从一次 64 位软
   件除法降到 4 条指令，但 CorsixTH 自身在 640x480 的软件光栅化没有改动，仍是余
   下的主要开销。现实预期是菜单 20–30 fps、游戏内 10–20 fps；60 fps 做不到。
4. citro3d/GPU present 路径（把 640x480 缓冲转成 tiled 纹理由 GPU 缩放）尚未实
   现，需要真机反馈才值得动。
5. 缩放在 3DS 上被锁死为 1.0。direct_zoom 路径把缩放作用到每个精灵，非 1.0 会让
   每次 blit 变成缩放 blit。
6. 电影、在线更新、MIDI 设备、Tracy、AnimView 和额外 CLI 工具在 3DS 构建中关闭。
7. 原版 Theme Hospital 数据不能随源码或二进制公开分发；SD 卡包只使用用户指定的本
   地数据。
8. 中文等大型 Unicode 字体会显著增加内存；首轮真机验收以英文为基线。
9. 裸眼 3D 路径完全排除，代码扫描会阻止相关 API 进入工程。
10. 启动日志写在 SD 卡上且不带缓冲。它在诊断阶段是必要的，但每行都会触发一次 SD
    写入；CorsixTH 初始化阶段输出较多时会有可感知的 I/O 开销。
