# 增量开发与真机候选

R48 起复用同一个上游组装目录、host/3ds 构建缓存、工具链与已验证的私有 SD 基线。
目录中的 R47 名称仅代表缓存位置，实际版本看 commit、ELF/3DSX 摘要与部署回执。

## 每次迭代

1. 查候选工作树和设备当前身份；保留上次可玩版本、日志、存档。
2. 在实际出问题的调用入口修改；运行相关测试。局部测试结论只覆盖所测项目。
3. 提交候选；重新组装并检查固定上游；在原构建目录增量交叉构建。
4. 真机综合候选运行完整 host 清单；日常定位可先跑相关测试，报告明确标注范围。
5. 用 `tools/make_sd_delta.py` 合成差量目录；原资源通过硬链接参与完整校验，随后释放临时目录。
6. FTP 仅传差量：旧文件双读一致后留本地备份，新文件暂存并读回，最后替换主入口；
   再读回身份并核对用户存档、配置、日志未改。中途失败保留事务记录和回退。
7. 用同一个小医院存档测试，读取日志更新 [滚动表](ROLLING_PLAN.md)。

最新实玩性能基线是R51 `bc0ded0`；R52 `cea5fc1` 已通过完整主机/交叉检查及差量安装读回，见[R52集中测试](R52_GPU_CANDIDATE.md)。
每次连接先核对当前地址、卡上实际身份及存档；部署成功与真机30FPS分别验收。
产品冻结提交与后续纯文档进度提交分别记录，二进制和测试始终绑定实际产品提交。

## 固定工程入口

当前主任务的 `当前工程.md` 和 `current/` 是本机导航入口：
`source`指向有效工作树，`upstream/build-host/build-release/build-3ds`指向复用缓存，
`evidence`指向本轮证据，`last-installed`和`last-played`分别指向最新安装与实玩记录。
这些链接只提供导航；实际构建继续使用原缓存路径，版本始终以提交和产物摘要判定。
`resource-baseline`只提供基础资源，必须叠加匹配差量并验证，不能当成最新完整SD包。
旧独立交付位于 `outputs/archive/20260902-legacy-deliveries/`，归档回执保留原路径与摘要；
旧源码工作树、工具链、转换缓存、存档和有效日志保持原位置。

## 验证频率

测试频率按改动风险控制：

| 场合 | 执行 | 明确边界 |
|---|---|---|
| 日常定位、单项小改 | 受影响的实际入口回归、C++检查、相关组装检查；需要3DS产物时增量交叉编译 | 记录选了哪些测试；不能标作全清单通过 |
| 综合真机候选、跨层改动 | 完整host清单、Debug/Release、真实交叉编译、差量合成核验 | R49/R50/R51采用此档；主机结果与真机结果分开 |
| 正式里程碑 | 独立干净构建、完整回归、完整私有包、真机关键路径和长期验证 | 保留开发缓存供下一轮使用 |

R49最终交叉构建19.6秒、差量生成5.3秒；完整host约12分钟，其中包含验证脚本自身
100次串行成功/失败路径及并发压力检查。重复压力检查不属于每个输入小改的必跑定位步骤。
不通过删测试、降低既定门槛或复用旧候选的PASS来缩短正式验证。

R51快速回归路由：改渲染构造/析构或画布接口时，同时跑`test_dual_screen_canvas`和`test_software_blitter`；
改日志刷新或全局观测状态时，同时跑`test_runtime_observation_flush`和`test_memory_telemetry_runtime`；
改CPU计算/批内查询时跑`test_cpu_hotspots`，改时钟/输入时加`test_playable_path`、`test_input_native_boundary`和`test_handheld_controls`。
抽取真实函数的测试必须同步包含真实生产头文件，不能用空桩替代新增行为。R51首轮漏带依赖导致两个测试编译失败，补齐后保留原断言并增测输出/释放，全清单重跑通过。
编译、组装、包身份和纯文档提交分开留痕；同一旧设备文件可复用已校验的双读备份，发布前重新核对其当前摘要和所有受保护用户文件。

打包器示例（参数须指向本轮冻结的真实产物）：

```sh
python3 tools/make_sd_delta.py \
  --baseline "$CTH3DS_SD_BASELINE" --repo . --output "$CTH3DS_DELTA_OUTPUT" \
  --replace "CorsixTH-3DS.3dsx=$CTH3DS_BINARY" \
  --replace "Lua/3ds/platform.lua=$CTH3DS_UPSTREAM/CorsixTH/Lua/3ds/platform.lua" \
  --replace "Lua/dialogs/resizables/file_browsers/save_game.lua=$CTH3DS_UPSTREAM/CorsixTH/Lua/dialogs/resizables/file_browsers/save_game.lua"
```

`delta.json` 记录旧/新文件摘要、候选身份、需要传输/复用的字节数和打包耗时。
其 `files/` 是差量，不能单独当成完整 SD 安装包。生成器不会接触设备。
二进制来源仍由交叉构建日志、链接检查和提交身份证明；合成目录校验只证明安装内容一致。

每次要检查**全部实际修改的运行文件**都已进入差量。转换规则、语言闭包、原始资源、
配置或新增媒体变化时走完整打包，不能将它们塞进 runtime-only 差量。
主机模拟/测试通过、交叉构建通过、传输成功、真机实玩通过分别记账。

## 性能对照

R52默认在可分配预算内使用Citro2D真实画布；关闭重复翻转副本，保留软件参考开关
`gpu-software.txt`。定时`gpu-work`提供完成队列、等待、图集换页和内存数据，
它们不等于硬件利用率。新增World/UI包容耗时同样不能与其内部温度/寻路耗时相加。
单次自动副本基准在专用目录运行，Normal/最高普通档各30秒预热与60秒采样；
强制暂停、速度变化或B取消使该样本失效。安装器需保护原Saves和标记基准输入摘要。
完整刷新延后至外层操作结束，采样结束后紧接的载入可能与完整窗口重叠。
分析时保留越界时间，优先使用全区间位于样本内的累计10秒摘要；不可把这些累计值相加。
R52的GPU改动另跑 `test_gpu_renderer` / `test_no_stereo`，
自动基准改动跑 `test_benchmark`；原渲染、保存、输入和观测路由仍保留。

- 软件参考路径开启翻转精灵缓存，所有方向与原纹理共用 6 MiB 上限；GPU路径关闭重复翻转副本。
- 可在应用目录放置空的 `render-reference.txt`，下次启动使用原翻转绘制路径。
  删除该单一开关文件后恢复优化路径；原版资源、存档不变。
- 同存档、同镜头、同语言、同速度：预热 30 秒，记录 60 秒，清晰/广角分别比较。
- `render-work`：实际绘制、缓存命中/缺失、退回通用翻转、解码像素、纹理预算。
- `input-queue`：采样、合并、按下/抬起、队列年龄/溢出。主动暂停从采样间隔统计中分开。
- 完整帧统计、游戏日期/速度、普通堆/线性低水位继续保留；Lua 占用包含在普通堆中。
- 软件阶段耗时不等于 CPU/GPU 硬件利用率；输入队列年龄不等于最终屏幕可见延迟。
- R51 `blit-probe`记录启动绘制对照及路径选择；两类样本各提速至少10%且校验和一致才选实验路径。
  `blit-reference.txt`可强制使用原SDL路径（只读开关，需下次启动）；`blit-work`记录真实使用/回退与元数据。
- `cpu-work`为温度、基础寻路、状态查询及Lua适配器的包容性区段耗时，重叠部分不能相加作CPU占用率。
  `simulation-budget`记录有界时钟的累计步数、欠账、丢弃量和重置；持续丢模拟时间不能用来通过30FPS验收。

## 真机最短回归路线

R51优先载入已读回的R49 `Slot2.sav`/`Slot3.sav`，核对原房间与员工。保留原存档作为基准，
恢复后另存备用槽；30秒预热，Normal与Max speed各保留约60秒静止样本，再保存/重开。
按候选版本核对控制，下表为R51：

| 操作 | 预期 |
|---|---|
| 下屏短点、连点、拖动 | 按下/抬起有序，无拖动粘住；反应时间另看日志 |
| 摇杆 | 白框移动；到边缘后的剩余位移滚图，菜单只移动观察框；触控笔按住时暂停滚图 |
| 十字键 / R+十字键 | 当前总览模式均不移动视野或鼠标；鼠标由笔控制，A确认前确保目标可见 |
| L | 清晰400×240 / 广角480×288，菜单也可手动切换；新对话框默认清晰 |
| Select / Start | 按上游五档循环调速 / 暂停恢复；暂停时调速不自动恢复 |
| Y / X | 切墙体显示 / 普通状态菜单、家具放置时旋转；其他菜单直接触摸 |
| 建房、放家具 | X 旋转家具，B 取消；触摸目标与上屏位置一致 |
| R+Start | 打开存档；三个槽位可直接保存，覆盖先确认 |
| 选中文本框后 A | 系统键盘；取消保留原名；本轮命名限制为英文、数字、空格、横线、下划线 |
| R+Select | 按键帮助 |
| 保存退出、重开载入 | 同一医院、人员、房间、进度恢复；存读档峰值有记录 |
| HOME / 合盖返回 | 输入无残留、音效与游戏状态正常；保存承诺按现有生命周期约定 |

R49的`control-edge`、`view-toggle`、`view-present`追踪L从输入到呈现；`display-stats`
同时记实际白框范围。源码、主机像素、上传通过均不能代替这一步实体按键验收。
`simulation-clock`与`workload`联合判断游戏时间实际加速多少，不把目标档位当成实测速率。
五档是Slowest→Slower→Normal→Max speed→And then some more→Slowest；
代码直接调用上游World:setSpeed，界面显示同名档位。没有新增或修改速度参数。

## 完整交付与清理

里程碑保留干净构建、全回归、完整私有 SD 包；公开源码不包含原版游戏与存档。
平时保留工具链、转换缓存和最新有效基线，不反复下载大包。
临时校验树用完自动删除。其余清理先确认无活动消费者；保留当前候选、上一可玩回退和有效证据。
