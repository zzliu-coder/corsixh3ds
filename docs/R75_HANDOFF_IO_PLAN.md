# R75 医生交接、保存写入与验收计划

## 边界与当前证据

承接 R74 的 b2cb0c2 中文、窗口持久化和勤杂工队列修订。设备当前版本仍为 71d37b4；本文件的施工完成项不代表真机验收。

正常业务链为：呼叫分配 → 步行抵达 → 房间接受员工并安排服务动作 → 呼叫完成。已复现旧代码在无法寻路时直接走完检查点、删除呼叫并触发空队列。R74 实玩三次医生警告是否全部属于该路径仍待现场验证。

保存链为：隔离临时文件 → 完成序列化 → 关闭文件 → 原子提交 → 恢复资源和运行状态。旧档在提交成功前保持有效。实玩保存耗时 2.749–12.426 秒，最慢 fwrite 累计 10.213 秒；当前粒度是 stdio 墙钟时间，不能拆成物理 SD 与文件系统耗时。

## 施工及销项顺序

| 顺序 | 工作 | 完成条件 |
|---|---|---|
| 1 | 房间交接契约修复 | 原版失败复现；正常接管、不可达、同房、拒绝、中断、旧动作及新归属测试通过 |
| 2 | 16/64 KiB 显式缓冲 | 默认保持 16 KiB；原格式字节一致；短写、关闭、清理和原子提交失败均保留保护 |
| 3 | 私有自动对照 | 同一暂停医院按 16/64/64/16 顺序写出；读回比较字节、完整耗时、最大写入停顿和内存；重载健康 |
| 4 | 动态设备保护 | 按当前所有存档及配置列举、读回、哈希备份；程序差量含新字体，二进制最后发布；旧事务明确审计 |
| 5 | 合并验证与构建 | 一次改变链路回归、完整原生目标与 ARM 目标构建、真实生成 Lua 初始化；来源与产物绑定 |
| 6 | 自动设备验收 | 私有繁忙医院、人员服务、连续存读、真实招募、末关往返、资源回收；读回明确逐项 PASS/FAIL/NOT_PROVEN |
| 7 | 保留有效结果 | 有实测收益才调整默认缓冲；保存中文 Git 提交和回退信息；计划按实际证据更新 |

本轮继续沿用上下屏和经营规则。音乐、语音不重复转换；已证明的中文/英文性能对比不重跑。系统键盘取消、物理 HOME、新中文视觉排版留给一次最短人工确认；既有键盘确认、合盖基本路径保留历史证据，不冒充新候选验收。

## 验收约束

- runner 使用私有输入副本、私有存档目录和独立配置，禁止覆盖玩家原件。
- 性能样本仅在模拟持续正常、无错误恢复失真时解释；30 FPS 不作硬性门槛。
- 局部宿主测试、完整构建、上传读回和实际游戏运行各自记录结果。
- 失败扩大到对应生命周期及所有调用方；不清理整个存档图、不用统一游荡动作掩盖房间错误。
- 重用固定上游、依赖缓存和已验证资源；测试集合按影响范围选择，全套测试未执行时明确记录。
