# R57：启动栈边界与成功路径

R56 `93dab8fa4378b5afde4a84548ea8f7a764227277` 真机启动 **FAIL**。
设备程序摘要与安装回执相同，Luma 转储代码片段与保留 ELF 逐字节相同。
PC `0x002f7a90` 位于 `memset`，LR `0x00135870` 回到 `register_lua_module`。

## 原因与修复

`g_observations = {}` 先创建 53632 字节临时对象，再拷贝到静态监控对象。
最终 ARM 函数栈帧为 53680 字节；程序链接的主栈仅 32768 字节。
SP 已越出栈映射，`memset` 保存寄存器时触发写异常。发生点早于 `boot_log_open()`，
所以旧 `boot.log` 仍标记 R55，不能作为 R56 运行记录。

成功路径为：静态对象原位清理→设定观测窗口→打开日志→注册 Lua→原有启动/自检/游戏流程。
监控对象禁止复制；reset 复用既有静态内存，旧操作队列与慢事件通过计数清空，旧 token 保持失效。
没有增加主栈、普通堆预算或新线程，保留 R56 的 GPU 预转换、温度缓存与细粒度日志。

同类扫描发现 `hash_file` 的 64 KiB 栈缓冲：最终帧 66088 字节。
改为 4 KiB 流式读取，摘要算法、输入范围、校验规则和文件格式不变。
该资源包路径当前通常未启用；作为同类栈风险一并消除。

## 验证边界

- 主机：实际观测组件重复 reset；旧事件/操作不泄漏，旧 token 无效，新事件正常。
- 资源回归：完整流式哈希、合法资源包与损坏包检查保持原结果。
- ARM：`tools/check_runtime_stack.py` 读取最终 ELF 的展开信息。
  启动/重置函数上限 1024 字节；观测输出上限 4096；其他移植函数 8192。
  缺失函数、缺失展开信息、未知动态 CFA 表达式或超额均阻断交叉构建；R56 故障 ELF 必须被拒绝。
- 这项检查约束单函数帧；整个调用链、第三方库递归与真实栈余量仍待真机测量。
- FTP 仅发布程序、版本清单与 R57 一次性 benchmark 标记。配置/存档/游戏资源原位保留。

R55 是最近可实玩基线。R56 的性能增益尚无真机证据；R57 继续同档自动采样，
再测招聘/突发窗口、保存及重进。30FPS、原速模拟、繁忙医院与长期稳定性继续 **NOT_PROVEN**。
