# R47：输入、观察窗口与资源基线

## 本轮边界

沿用 R46 的唯一软件画布：640×480；上屏 400×240 原像素观察窗口，
下屏 320×240 全画面缩略图，白框标出上屏范围。触摸整个下屏均有效，
触摸位置乘二进入同一游戏光标。上屏随光标移动，菜单/对话框出现时定位。
当前通过上屏阅读文字；下屏缩略文字的可读性不作为本轮通过条件。

成功路径是“看到入口 → 定位同一光标 → 确认 → 执行 → 返回地图”。
原生 Lua 5.4 光标接口接受整数；模拟摇杆的小数位累计到下一帧，
触摸、精确方向键、UI/场景更换、取消和挂起会清理旧累计。
方向键单按 1 逻辑像素，长按重复 4 像素。普通地图里摇杆移动地图；
菜单/对话框里摇杆移动光标。X 从地图打开顶部菜单并定位首个入口；
A 确认，B 关闭顶部菜单。房间/物品状态仍遵循原有放置和旋转语义。

## 第一轮真机复测

使用本轮读回匹配的同一二进制；先退出 ftpd，再进入 Homebrew Launcher，
打开唯一的 CorsixTH-3DS。启动条应显示 R47。

1. 在主菜单轻推、推满、斜推摇杆，各来回数次；混用触摸、方向键和 A。
   预期光标可见、轻推有连续累计、无 FATAL，确认落在当前可见位置。
2. 进入第一关；关闭任务说明后按 X。预期上屏可读到顶部菜单，
   摇杆移动菜单光标，方向键微调，A 展开/选择，B 返回地图。
   再触摸下屏最下方工具栏，预期上屏跟随到相应位置。
3. 空医院正常速度运行至少 90 秒；期间移动地图、打开关闭建造窗口。
   预期地图、两屏和输入继续响应。音效是否实际可闻单独记录。
4. 从游戏菜单正常退出，再开 ftpd。记录大致卡顿时机即可，
   完整统计由电脑读取日志。发生 FATAL 时先拍照，再按 B 返回并开 ftpd。

这四步保留为独立真机待验证项。主机测试、交叉链接和上传读回均不能替代。
本轮供复测，中文、音乐、后续关卡和长时间稳定性尚未放行。

## 监控的含义与成本

| 记录 | 可回答的问题 | 边界 |
|---|---|---|
| stage / S100 / level-ready | 冷启动、进关分别耗时多久 | 结合相同候选和存档身份 |
| perf（10 秒） | 短运行的双屏成功/失败、平均/P95/最大帧间隔、未出帧长停顿、内存余量 | 同一窗口的累计快照，不能将各行相加 |
| frames / span（60 秒或退出/错误） | 完整帧间隔，逻辑、绘制、上下屏输出、GC、存读档耗时 | 阶段墙钟时间；P95/P99 为直方图上下界 |
| display-stats / bottom-stats | CPU 像素复制与 SDL 输出调用各花多久 | 软件提交时间；GPU 利用率与物理扫描完成时间 UNKNOWN |
| workload（10 秒） | 场景、病人、员工、房间、日期、速度、语言和音乐配置 | 音乐配置不证明音乐已播放 |
| observed-memory / operation-memory | 语言、音效、精灵、换关、存读档前后占用 | 采样峰值下界；Lua 属普通堆子集，避免相加 |
| input-failed / FATAL | 哪个输入、方向、场景与当前光标触发异常 | 不复现未知的历史第一次操作 |

日志在内存累加，低频汇总。boot.log、boot.previous.log、boot.older.log
保留最近三次启动，每份最多 1 MiB；正常写入预留 16 KiB 错误空间，
达到上限明确标记截断。错误时先保存尚未完成的阶段及长停顿，
再显示错误页；未完成阶段不伪装为成功。main-thread stderr 汇入同一有限写入器。
log_us 为 boot_log 累计写入耗时；workload_us 包括采样及其日志写入，
两者有重叠，不能相加当成总监控成本。真机需实际检查其开销。
无联网遥测、无每帧截图、无监控造成的无界资源队列。

## 基准与下一阶段

先用上述复测关闭输入阻断，再固定同一版本/资源/配置/存档：
主菜单、第一关空医院、约 20 病人的固定医院，预热 30 秒，采样 60 秒，
各重复 3 次；冷启动、进关、保存和读档分别记录。首次复测不要求用户
手工凑齐全部基准场景，后续由保留存档形成可重复对照。

正常经营目标为 30 FPS（约 33.3 ms），同时报告 P95/P99、最长停顿和
游戏日期推进速度；平均 FPS 不单独决定流畅度。稳定关卡普通堆余量
8 MiB、存读档过程中 4 MiB 为现有最低门槛，并非大关容量保证。
后续繁忙关卡、重复换关、音效并发、中文字体、音乐播放和长时间运行
须再次在完整功能配置下测量。

阶段 B 接入已保留的中文字体与文件流式音乐，按关闭/开启作同版本成本对照；
先一首音乐完成播放/停止/恢复，再处理其余曲目。热点优化由实际完整帧
和加载内存数据排序；通用资源框架、全套界面与整套 GPU 重写保持冻结。
