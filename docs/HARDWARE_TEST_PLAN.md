# Old 3DS 真机验收计划

虚拟机能证明逻辑、接口、确定性和内存边界；以下项目必须在 Old 3DS 上完成。

## 开机后的前 5 分钟：先取证，再判断

0.4.0 的每一轮真机结论都是 NOT_PROVEN，因为设备上没有留下任何可读的证据。0.5.0
之后，任何一次真机运行都必须先做完这三步，再谈别的：

1. **确认跑的是哪个二进制。** 下屏状态栏第二行形如
   `B5 W3 V63 M40 0.5.0 LUA`。最后两段是 overlay 版本和适配层来源。
   如果版本不是刚部署的那个，说明启动的是旧的 `.3dsx`，后面所有观察都无效。
2. **读适配层来源标签。**
   - `LUA`：正常，SD 卡上的 `app.lua` 是打过补丁的。
   - `SD`：SD 卡上的 `app.lua` **不是**打过补丁的版本，运行时自己兜住了。
     说明打包用的上游树没有先跑 `tools/integrate_corsixth.py`。
   - `EMB`：SD 卡上的 `Lua/3ds/platform.lua` 缺失或加载失败，用了内置副本。
   - `FAIL`：完全挂不上，具体 Lua 错误在下屏和 boot.log。
3. **取回启动日志。** 退出（或强制重启）后开 FTPD：

   ```bash
   python3 tools/old3ds_fetch_log.py --host <3DS 的 IP> --out run/device-logs
   ```

   `scripts/old3ds_cycle.sh` 会在部署前自动做这件事。日志不带缓冲，最后一行就是
   最后真正执行到的位置。

   注意：部署会覆盖整个 `/3ds/corsixth`，所以**必须在下一次部署之前**取。

只有这三步都有结果，才能把某一项写成 PASS 或 FAIL；否则仍然只能写 NOT_PROVEN。

## P0：性能基线（0.5.0 新增）

进入主菜单后从下屏读一次帧时间（`th3ds.performance()` 暴露 average/p95/max）。
记录三个场景：主菜单、空医院、20 个病人的医院。

预期区间（60 fps 做不到；见 `docs/PERFORMANCE.md` 里的成本模型）：

| 场景 | 目标 average | 判为异常 |
|---|---|---|
| 主菜单 | ≤ 50 ms | > 100 ms |
| 空医院 | ≤ 70 ms | > 150 ms |
| 20 病人 | ≤ 100 ms | > 200 ms |

如果 present 阶段本身仍然很贵，boot.log 里 `present: ... exact reduction=yes (1/2)`
这行会告诉你窗口尺寸是否还是 640x480；不是的话 present 在做重采样。


## P0：启动闭环

1. Homebrew Launcher 能发现并启动 `CorsixTH-3DS.3dsx`。
2. 能读取 `sdmc:/3ds/corsixth/CorsixTH.lua` 和合法原版数据。
3. 进入主菜单、载入第一关、显示医院画面。
4. 上屏无旋转、撕裂、越界或错误色序；下屏能独立刷新。
5. 退出回 Homebrew Launcher，无黑屏和崩溃。

通过标准：连续冷启动 10 次全部成功。

## P0：完整经营闭环

1. 摇杆移动镜头；十字键精确移动。
2. 下屏进入 Build，拖出合法房间矩形。
3. 放置门和必要物品，雇佣员工。
4. 病人进入房间并完成一次诊疗。
5. 快速保存、退出、重新启动、快速读取。

通过标准：第一关从空地完成一次治疗，存读档后状态一致。

## P0：稳定性和内存

场景：第一关、中期医院、人员密集、频繁切换全屏窗口、连续滚动镜头。

记录：

- 启动可用内存；
- 进入关卡后可用内存；
- 30、60、120 分钟后的可用内存；
- 最低帧率、平均帧率、最长帧；
- 纹理创建失败、Lua 错误、音频欠载次数。

通过标准：运行 2 小时无崩溃；可用内存无持续单调下降；正常经营时目标 30 FPS，重场景允许短暂下降。

## P0：生命周期和存档安全

分别在普通状态、打开菜单、拖建房间、保存期间测试：

1. 按 HOME，返回游戏；
2. 合盖 30 秒、5 分钟、30 分钟；
3. 电量较低时合盖和恢复；
4. 保存后立即 HOME/合盖；
5. 人为留下 `.tmp` 或 `.bak` 后启动恢复。

通过标准：游戏自动暂停；恢复后输入、画面、声音正常；正式存档始终可读；不存在零字节正式存档。

## P1：输入和触摸

- 触摸四角、边缘和页签边界；
- 快速单击、双击、长按；
- 斜向拖房间和反向拖房间；
- 十字键长按重复；
- A/B/X/Y/L/R 在世界、菜单、对话框、建造四种上下文中的含义。

通过标准：无幽灵点击、无按键粘连、触摸命中和视觉区域一致。

## P1：声音

- DSP firmware 存在与缺失两种情况；
- 音乐、广播、环境音和 UI 音效；
- HOME、合盖、恢复后的音频；
- 30 分钟连续播放；
- 系统音量滑块变化。

通过标准：无持续爆音、卡死、音频线程泄漏；恢复后声音能继续或安全重启。

## P1：SD 卡和数据差异

使用至少两张不同品牌/容量 SD 卡和两套合法原版数据来源，测试大小写、长路径和碎片化目录。

通过标准：打包器能拒绝缺文件数据；合法数据能稳定载入；清单能发现损坏文件。

## 建议日志

每次真机测试保留：固件版本、Luma 版本、SD 卡、构建 SHA-256、原版数据来源、测试时长、最低内存、异常步骤和复现概率。
