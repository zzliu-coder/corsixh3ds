# R63 自动复跑适配

状态：代码与定向宿主验证、实际装配、ARM构建通过；真实游戏启动、结果回返与长时压力以后续真机回执为准。此次未新增游戏算法、未改变随机调用、原版速度档或双屏操作。

## 成功路径

主机生成全新run ID及候选/配置/输入摘要 → 已验证的runner暂停FTP后启动游戏 → 游戏验证参数和已安装Lua → 在本run私有目录读写配置、热键、日志与存档 → 统计实际完成模拟与成功呈现 → 正常退出 → runner重新启动并出具回执 → 主机读回结果及核对原档保护。

复用old3ds-runner `cab2721` 的协议和Rosalina正常回返实现，保留源许可证及来源声明。没有新增FTP服务器或开启InputRedirection。主机工具使用现成runner CLI；本适配尚不提供任意游戏操作录制/回放。

## 目录与身份

- 普通入口仍为 `/3ds/corsixth/CorsixTH-3DS.3dsx`；runner从自己的 `/runs/<id>/program.3dsx` 启动同一候选。
- 每次运行拥有自己的 `save/` 与 `artifacts/`。原 `Saves/`、配置、热键和单次benchmark标记不作自动改写。
- 新二进制与新Lua须成套安装和成套回退。旧二进制缺少runner接口，不能混用新App。
- Lua树、测试输入、小型安装清单逐项绑定；大型媒体复用既有安装证据，结果明确记录本次未完整重验媒体。
- `tools/prepare_runner_benchmark.py` 只准备参数，不联网。`zh-on`、`expanded-zh-on`、`matrix` 分别用于常态中文、扩建中文和有必要时的媒体矩阵。预热/采样1–60秒，压力0–22分钟；1秒只适合协议夹具，不作为有效性能测量。

## 验证取舍

阶段进度写入不可变的 `artifacts/progress-0001.kv`、`progress-0002.kv` 等快照，
每份包含完整run身份、`checkpoint_sequence`和`snapshot_complete=1`。读取方先核对
身份和完整KV格式，再取完整快照中的最大序号；`.tmp`仅供故障诊断，不计作完成快照。
快照是该次阶段的观测记录，早先样本保留在早先序号中，不能把最大序号当作全部历史。
每run最多48份快照，每份最多16KiB，连同同名tmp的保守预算共96个，在128个artifact预算中保留其他证据空间。
每次经过独占临时文件→write→flush→fsync→close→全新final名称，成功后才增加序号。
已有final或遗留tmp均拒绝覆盖；失败保留旧快照和tmp，后续运行使用新run ID。
错误立即记录失败阶段和errno。宿主故障注入验证这些边界；真实SD上的底层故障根因
和恢复效果仍须按真机证据判定。

日常先做一轮短中文常态、私有保存/重载及自动回返，再补尚未完成的扩建医院压力。已完成英文关音乐、中文关音乐样本留存。字体或声音路径改动时补对应媒体回归。

成功呈现次数与同区间elapsed、World/游戏小时/实体成功更新量分开记录。完整样本使用 `sample_N_*`；成功退出中的 `partial_*` 可能包含最终保存/清理，分析器不得纳入FPS。声库已装载不证明真实播报已听验；历史样本不证明语言或音乐零成本。

恢复副本的静态存读档结果与未来行动分账，`recovery_behavior_outcome`仍为NOT_PROVEN。原档修复的实际未来行为需独立闭环。

取消与需玩家选择的事件归NOT_PROVEN；游戏、存档、清理或退出错误归FAIL。终态WORKLOAD-END只说明工作阶段结束；PASS还要核对结构化result与新launcher回执。硬件崩溃后自动回返能力仍有边界，超时保留当前run和锁供诊断，不能盲目重投。
